# Papercuts

Record small, unexpected obstacles that cost time, caused confusion, or required investigation while completing a request. A papercut is not a task log, status update, known project rule, or major incident.

Use one Markdown file for each papercut. This preserves stable metadata, avoids merge conflicts, and makes later review and automation simple.

## When to record

Record a papercut only when all conditions are true:

1. It was unexpected from the available request, code, or tool documentation.
2. It caused a real delay, failed action, ambiguity, or avoidable rework.
3. It is resolved well enough to state a concrete resolution or safe workaround.
4. It has reuse value for a future agent, skill, or project document.

Do not create a note for routine work, expected validation failures, unresolved problems, secrets, private user content, full prompts, access tokens, cookies, or complete tool transcripts.

When the user asks to record papercuts during a task, finish the requested work first. Record only papercuts that arose while doing that work. Do not interrupt the main task merely to create a note.

## Configuration

Load TOML from `$PAPERCUTS_CONFIG` when set. Otherwise load `${XDG_CONFIG_HOME:-$HOME/.config}/macklinu/skills/papercuts.toml`.

Example configuration:

```toml
version = 1
papercuts_root = "/absolute/path/to/papercuts"
```

The configuration is private. Do not add it to a repository or include its personal path, vault name, or owner name in public output.

Before reading or writing a papercut, run:

```sh
python3 scripts/validate_config.py <config-path>
```

The validator writes one JSON result, exits with status 0 only for valid configuration, and never changes files. Stop without changing papercuts when validation fails.

`papercuts_root` MUST be an existing absolute directory. The CLI creates notes only inside this directory.

## Note contract

Every note has YAML frontmatter with these fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | UUID | Stable identifier, generated by the CLI. |
| `title` | string | Factual 3–12 word title. |
| `created` | ISO 8601 timestamp with numeric UTC offset | When the papercut note was created. |
| `status` | `resolved` or `workaround` | `resolved` fixes the cause; `workaround` safely bypasses it. |
| `cwd` | absolute path | Working directory where the agent observed the obstacle. |
| `repository_root` | absolute path or `null` | Git worktree root when known. It differs from `cwd` when the agent works in a subdirectory, such as a package in a monorepo. |
| `git_branch` | string or `null` | Active branch when known. |
| `git_commit` | full Git object ID or `null` | HEAD commit when known. |
| `agent` | mapping | Agent runtime metadata. |
| `tooling` | list of strings | Relevant tools, commands, libraries, or systems. |
| `tags` | list of strings | Lowercase, slash-safe retrieval tags. |
| `sources` | list of strings | Relevant non-secret paths, issue URLs, or documentation URLs. |

The `agent` mapping has these required fields: `runtime`, `provider`, `model`, `session_id`, and `task_id`. Values may be `null` when unavailable. `runtime` is one of `omp`, `opencode`, `pi`, `claude-code`, `codex`, `cursor`, `other`, or `unknown`.

The Markdown body has these exact sections:

```markdown
## Papercut

What unexpectedly failed, surprised the agent, or created ambiguity. Include the observed behavior and the relevant constraint. State facts, not guesses.

## Resolution

The concrete change, command, or decision that resolved the issue. State whether it fixes the cause or is a workaround.

## Prevention

A specific improvement to a skill, tool, codebase document, or workflow. Use `None identified.` only after considering a prevention action.
```

Use `sources` for evidence. Cite only paths and URLs that a future agent can safely access. Do not put private paths outside `papercuts_root` in the body merely to provide context; use neutral names when required.

## Create a note

Build one JSON input object. Required input keys are `title`, `status`, `cwd`, `agent`, `tooling`, `tags`, `sources`, `papercut`, `resolution`, and `prevention`. `repository_root`, `git_branch`, and `git_commit` are optional and become `null` when absent.

```json
{
  "title": "Validator rejected a valid-looking path",
  "status": "resolved",
  "cwd": "/work/project",
  "repository_root": "/work/project",
  "git_branch": "main",
  "git_commit": "0123456789abcdef0123456789abcdef01234567",
  "agent": {
    "runtime": "omp",
    "provider": "openai",
    "model": "model-name",
    "session_id": null,
    "task_id": null
  },
  "tooling": ["python3", "TOML"],
  "tags": ["configuration", "validation"],
  "sources": ["scripts/validate_config.py"],
  "papercut": "The path looked valid but the validator required the target directory to exist.",
  "resolution": "Created the configured directory, then reran validation successfully.",
  "prevention": "Document that papercuts_root must already exist."
}
```

Run the CLI with the JSON object on standard input:

```sh
python3 scripts/create_papercut.py <config-path>
```

The CLI validates both configuration and input, generates `id` and `created`, writes a new UTF-8 Markdown file atomically, and prints JSON with `path` and `id`. It never overwrites a note. The filename is `YYYY-MM-DD — concise-title--<first-8-id>.md`.

If the CLI rejects input, correct the input and retry. Do not create a hand-written partial note or weaken validation. After a successful write, read the created note and confirm its frontmatter and three body sections describe the resolved papercut accurately.

## Review and improve

When asked to review papercuts:

1. Read the note frontmatter and body completely before changing it.
2. Group recurring causes by `tags`, `tooling`, and `agent.runtime`.
3. Separate evidence from inference. A repeated note shows a pattern; it does not prove a root cause.
4. Propose a precise skill, tool, or documentation change. Link the supporting papercut IDs.
5. Preserve `id` and `created`. Update `status` only when a workaround becomes a cause-level resolution.
