# Setup tooling

Use the smallest complete baseline. Read repository instructions first. Preserve existing manifests, scripts, pins, lockfiles, ignore rules, and hooks unless the task replaces them.

## Choose the path

- New or empty Node root: use the initialization sequence below.
- Existing Node root: inspect its manifest, workspaces, lockfile, ignores, and hooks. Add only missing parts.
- Existing competing tool: follow the requested migration scope. Do not leave two active conventions.

## Initialize safely

For a new root, confirm Nub's target files are absent, then run:

```sh
nub init --yes --no-install
```

Never use `--force` in an existing repository. Keep the `packageManager` and `devEngines` values generated by installed Nub. The verified new-project baseline with Nub v0.8.3 produced `packageManager: "nub@0.8.3"`; do not hard-code it. A global Nub upgrade does not rewrite an existing repository pin. Nub provisions the version pinned by that repository.

Before making Nub the exclusive Node toolchain, generate Node ignore rules and install its operating skills:

```sh
npx gitignore node
npx skills add https://github.com/nubjs/nub --skill nub
npx skills add https://github.com/github/awesome-copilot --skill conventional-commit
```

Review the `.gitignore` diff. `github/awesome-copilot@conventional-commit` is the selected commit skill. Read the Nub skill before the next Node command and the Conventional Commit skill before committing. Then use Nub instead of `node`, `npm`, `npx`, `pnpm`, or `yarn`; use `nubx` for installed local CLIs and `nub dlx` for temporary tools.

Make the root manifest private and declare both workspace locations:

```json
{
  "private": true,
  "workspaces": ["apps/*", "packages/*"]
}
```

Put runnable or deployable applications in `apps/*`. Put reusable libraries and shared tooling in `packages/*`. Create only needed directories. A Nub-native install writes `nub.lock`; commit it, not `package-lock.json`.

## Configure OxC, Vitest, and Lefthook

Nub initializes new roots with TypeScript 7. At the workspace root, ensure these development dependencies are present:

```sh
nub add -D -W typescript@^7 @types/node oxlint oxfmt vitest lefthook
nubx oxlint --init
nubx oxfmt --init
```

Keep the generated Oxlint and Oxfmt defaults. Add this property to both `.oxlintrc.json` and `.oxfmtrc.json`:

```json
"ignorePatterns": ["vendor/**", "repos/**"]
```

Every Oxlint and Oxfmt runtime call must include `--disable-nested-config`. Let Oxfmt discover files from the repository root; its config and ignore rules define the boundary:

```json
{
  "scripts": {
    "typecheck": "nubx tsc --noEmit",
    "lint": "nubx oxlint --disable-nested-config .",
    "format": "nubx oxfmt --write --disable-nested-config",
    "format:check": "nubx oxfmt --check --disable-nested-config",
    "test": "nubx vitest run"
  }
}
```

Vitest discovers `.test.` and `.spec.` files without configuration. Add `.vitest/` to `.gitignore`. Add a `vitest.config.ts` with `test.projects` only when workspaces need distinct test configuration or environments.

Configure `lefthook.yml` to pass only staged matching files. `--no-error-on-unmatched-pattern` lets each filtered command succeed when ignore rules leave no files. `stage_fixed: true` stages formatter changes and is valid for `pre-commit`:

```yaml
pre-commit:
  commands:
    lint:
      glob: "*.{js,mjs,cjs,jsx,ts,mts,cts,tsx}"
      run: nubx oxlint --disable-nested-config --no-error-on-unmatched-pattern {staged_files}
    format:
      glob: "*.{js,mjs,cjs,jsx,ts,mts,cts,tsx,json,jsonc}"
      run: nubx oxfmt --write --disable-nested-config --no-error-on-unmatched-pattern {staged_files}
      stage_fixed: true
```

## Verify

Run the configured checks:

```sh
nub install
nub run typecheck
nub run lint
nub run format:check
nubx lefthook validate
nubx lefthook install --force
```

After the project has a real test, run `nub run test`.

## Commit

Review the diff, run the focused checks, and stage only intended files. Read the installed `conventional-commit` skill, then commit as part of the setup task. Push or open a pull request only when requested; some repositories have no GitHub remote. Report changed files, validation, and the commit SHA, plus the pull request URL when one was opened.
